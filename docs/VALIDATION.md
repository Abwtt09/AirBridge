## Joint real-device test — local development app

The user confirmed successful audio-card discovery, selection and audible
iPhone → Windows output on iOS 27 on 2026-10-15. Receiver events showed actual
RTP synchronization, audio UDP packets, decoder frames and nonzero RMS. The
selected endpoint was SteelSeries Sonar Media. After initial mild stuttering and
an IPv6 policy rejection were addressed, the user confirmed successful connection,
stable audible playback and the correct iPhone 16 model/icon. The active session
reported `iPhone17,3`, `streaming`, nonzero RMS and no engine error. This validation
used Stable WASAPI buffering and audio-only scheduling without client-video
timestamp scheduling. Other buffer presets and iPad hardware remain untested.

The local IPv6 listener now matches actual adapter prefixes. Native prefix-policy
tests passed for five IPv4 and seven IPv6 on-link cases, including a global-format
IPv6 prefix, plus off-link rejection, invalid prefix boundaries and mismatched
link-local scope rejection. RTSP `/info` returned success over IPv6 loopback and
ten local IPv6 interface addresses. Clean-source reproduction and idempotency
checks passed for all eleven native integration files.

The Windows UDP fallback fix has a native loopback regression probe using the
actual `kernel_timestamp_session_recv` function: repeated sender-address reads
and reads with no sender-address buffer passed. This test is distinct from the
real iPhone playback confirmed by the user.

## Remaining real-device acceptance checklist

Record Windows build, iPhone model, iOS version, router, connection type and selected playback endpoint. The iPhone is operated by the user; the agent observes local receiver diagnostics.

- [ ] Launch the packaged AirBridge application on Windows 11 x64.
- [ ] Connect PC and iPhone to the same trusted network and configure Private firewall access.
- [ ] Complete onboarding only after the receiver starts successfully.
- [ ] Open the iPhone AirPlay **audio** selector; verify the configured name appears.
- [ ] Select AirBridge, play supported audio and hear stereo through Windows speakers.
- [ ] Confirm UI state/client name and measured activity reflect the real session.
- [ ] Change iPhone volume, app volume and app mute; verify Windows master volume is unchanged.
- [ ] Change output devices and reconnect after the documented engine restart.
- [ ] Unplug an output device and confirm visible default fallback/recovery.
- [ ] Disconnect/reconnect the iPhone repeatedly, with silent and paused streams.
- [ ] Close/minimize to tray and verify continued playback; reopen from tray.
- [ ] Quit and verify no owned engine/helper process remains.
- [ ] Restart the app and verify settings and discovery recover.
- [ ] Toggle Wi-Fi, change IP, resume from sleep, and recover discovery/playback.
- [ ] Exercise port conflicts, missing DLLs, decoder errors and engine crashes.
- [ ] Test light/dark/system theme, keyboard controls, screen reader and reduced motion.
- [ ] Test optional startup launch and close-to-quit behavior.
- [ ] Test current iOS versions and document unsupported app/protocol combinations.
- [ ] Test a clean offline Windows installation with WebView2 already installed.

Real iPhone discovery, source-to-speaker playback and model recognition were confirmed jointly in the local app. Automated native desktop checks cover background operation and packaged-executable launch. The unchecked items above remain acceptance work for the installed release and wider hardware coverage; they are not inferred from upstream claims.

## First-release update verification — 2026-10-16

- Frontend formatting and production build passed. Three update URL trust tests passed.
- Strict all-target Clippy and fourteen Rust tests passed with the updater integration.
- The real NSIS installer verified with the production Tauri public key. The same test rejected a changed byte and a manifest falsely relabeling it as version 999.0.0. The integration test uses Common Controls v6, as required by its native Windows dialog dependencies.
- The newly built native WebView test passed receiver startup, forced child-crash recovery, explicit output selection, event rendering, settings persistence, close-to-tray continuity, stop, graceful quit, diagnostic log display and update controls. Original settings were restored.
- The harness first needed to drain automatic startup before requesting its own receiver generation; this was a test sequencing issue. The successful complete report is artifacts/ui-smoke.json.
- A full installed-old-version to installed-new-version upgrade cycle and clean-VM installation remain pending. Signature checks and current-version endpoint checks do not establish those behaviors.

## Published release verification — 2026-10-16

v0.1.0 was published at https://github.com/Abwtt09/AirBridge/releases/tag/v0.1.0. All twelve uploaded assets matched GitHub server-side SHA-256 digests and sizes. The public latest.json endpoint returned version 0.1.0, the expected installer URL and the exact signature. A new real native WebView session checked through Settings → About, displayed “You’re up to date”, and retained receiver advertisement. The test quit gracefully. This confirms current-version discovery, not a full old-to-new installation cycle. The Windows release workflow was validated with actionlint 1.7.12 and registered as active on GitHub; it has not yet run for a subsequent version tag.
